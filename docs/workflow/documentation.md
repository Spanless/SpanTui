# 文档与注释规范

## 1. 原则

1. **以代码为准**：只写现行行为与其原因；不写历史、计划、过渡状态。
2. **单一所有者**：每条事实只在一篇文档展开，其他处链接。
3. **只写代码表达不了的**：不复述源码、属性表或通用常识；能由脚本检查的规则只写一句加脚本名。
4. **写短**：陈述句，一句一事，附必要的原因；不用强调词堆砌。
5. **原地更新**：替代即删除；路径、标题、正文不带"新版""旧""临时""草稿"等标记。

## 2. 目录与层级

| 层级 | 内容 | 位置 |
|---|---|---|
| L1 | 安全底线、流程、项目特有约定 | `AGENTS.md` |
| L2 | 域边界、子域索引、本域完成标准 | `docs/<域>/overview.md` 或域顶层文档 |
| L3 | 模块行为、生命周期、边界条件 | `docs/<域>/<功能>.md` |
| L4 | 查表参考：配置键、术语、命令行 | `docs/reference/` |

- `workflow/`：开发流程；`architecture/`：跨层不变量；`ui/`：QML 层；`services/`：C++ 服务域；`reference/`：参考；`legal/`：许可。
- 文件名 kebab-case；新内容优先并入最相近的现有文档。
- 上层只放摘要与链接。
- L2 文档末尾设 `## N. 本域改动完成标准`：按改动类型分小节，每条 `- [ ]` 祈使句，对应一个具体失败点。

## 3. 文档内容

- 不写行号（`check-docs` 的 `lines` 规则）、提交哈希、核对日期、机器路径；示例路径用 `C:\Qt` 或 `<占位符>`。
- 被替代的参数、目录、行为直接删去，不留"（已移除）"条目。
- 约束对任何开发者都成立，不针对某个工具或人。
- 源码与文档、或两套实现互相矛盾且未裁决时，不把任一方写成标准，在交付说明中列出双方与证据。

## 4. 代码注释

注释只写代码表达不了的内容：

- **保留**：非显然的原因、约束与不变量；会因改动复发的陷阱；外部协议、平台缺陷或规范的依据。
- **删除**：复述名称、签名或下一行代码的说明；改动历史与"之前/现在/改为"；分节标记、位置标记；已被结构保证、不会复发的旧坑。
- 机器读取的标记保留：`// style-ok: 原因`、`# noqa`、SPDX 与许可证头。
- 第三方代码（`vendor/`）不改。

## 5. 归属映射（`docs/ownership.json`）

源码路径 → 主责文档的唯一映射，`tools/check-ownership.ps1` 查询与校验。

- 增删、合并源码目录时增删对应 entry；`docs` 只列存在的文档。
- 高影响对象新增、重命名或移动时更新 `highImpact`。

## 6. 验收

- [ ] `tools/check-docs.ps1` 通过（链接与锚点、引用路径、源码中的文档路径、`docs/index.md` 覆盖全部文档、`docs/legal` 记录的 vendor 二进制哈希、ownership 映射）。
- [ ] 文中的类名、函数名、组件名、设置键均存在于当前代码。
- [ ] 源码目录或核心控制器变动已同步 `ownership.json` 与 [状态所有权](../architecture/state-ownership.md)。
- [ ] `git diff --check` 无尾随空格。
