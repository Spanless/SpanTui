# Changelog

All notable changes to SpanTui are recorded here. Versions follow [Semantic Versioning](https://semver.org/); the version number lives in `CMakeLists.txt` (`project(SpanTui VERSION ...)`) and releases are tagged `v<version>`.

## [Unreleased]

- Updates now run the new version's setup program: an installed copy downloads `SpanTui-<version>-Setup.exe` from the latest stable GitHub release, checks its digest and closes; the setup shows only its progress window and starts the new version when it is done. Once confirmed, a progress card lists each step (download or copy, verify, start the setup) with its percentage and the megabytes done; copying, hashing and starting the setup run off the interface thread, so the window no longer freezes while Windows checks the new setup. Hiding the card keeps the update going; the Updates row and Settings > General reopen it. Updating from a local build folder moved to the new Settings > Developer page; while it is on, only that folder is checked. The folder is the one above the version folders `dev package` writes (`target\release` or `span-tui` under the artifact root), so it stays the same across versions: the newest package in it is offered, and its `release-manifest.json` names the setup and its digest. Portable copies only report a new version and open its download page. The standalone updater (`SpanTui-updater.exe`) is gone; setup deletes it and the files it left behind. Updating no longer asks for administrator rights again when the Explorer menu certificate is already trusted. Update settings live in the `[update]` group of `settings.ini`; the old local update folder is not carried over.
- Fixed: the workspace window could open with a second, native title bar and its bottom edge cut off until it was resized.
- Fixed: the first launch warned that the pipeline cache file could not be opened.
- The first launch no longer opens a folder picker; without projects the sidebar shows a compact empty state with the Remote section right below it.
- New installs start in Simplified Chinese, with interface text at 14 px and auxiliary text at 12 px; saved settings are kept.
- Fixed: the default shell picker in Settings > Terminal lost its name once its list had been opened.
- Settings > General picks the language from a dropdown; each language is named in itself (English, 简体中文).
- Every loading indicator uses a new icon: a prompt with a comet of dust circling it at a steady speed. Fixed: the old spinner raced and stuttered, and icon animations ran too fast when the window was on a monitor with a higher refresh rate than the primary one; icon motion is now timed by the wall clock.
- All files the program writes live under one data root: `%LOCALAPPDATA%\SpanTui` (the first launch moves an existing `%APPDATA%\Span\SpanTui` there), the `data` folder of a portable package (`portable.txt` next to the exe), or `--data-dir <folder>`. Settings move from `Span\SpanTui.ini` to `settings.ini` automatically; in-app updates write their setup log to `logs\update-setup.log`; the Qt pipeline cache moves from `%LOCALAPPDATA%` to `cache\`.
- `SPANTUI_CONPTY=system` and `SPANTUI_TERMINAL_VIEWPORT_TRACE` became the launch options `--conpty=system` and `--trace-viewport[=0|1]`.
- Development: tooling reads an optional `.env`; dev runs, tests and scratch stay in `.dev\`; new `dev.bat clean`.
- Development: build trees and packages moved from `build\` and `release\` to `target\build` and `target\release\<version>\windows-x64` (the same per-version layout as under `SPANTUI_ARTIFACT_ROOT`). `SPANTUI_BUILD_ROOT` and `SPANTUI_ARTIFACT_ROOT` (formerly `DEVELOP_ARTIFACT_ROOT`) move them elsewhere; the tooling no longer creates or follows junctions.
- Development: packages under `SPANTUI_ARTIFACT_ROOT` go to `span-tui\<version>\windows-x64` instead of `releases\spantui\<version>\windows-x64`; move existing version folders there and point the local update folder at the new parent. Tests keep their TEMP, APPDATA and LOCALAPPDATA in `.dev\tmp\tests\<test>\`, and font builds work in `.dev\tmp\fontbuild`.
- Development: parallel tasks use git worktrees. `dev.bat worktree add|list|remove|prune` manages them; each worktree has its own build tree (`<SPANTUI_BUILD_ROOT>\wt-<id>`, or its own `target\build`), `.dev\` and `dev` lock, and reads the main checkout's `.env`. `SPANTUI_BUILD_DIR`, one build tree shared by every checkout, is no longer read; set `SPANTUI_BUILD_ROOT` instead.
- Development: the packaging pipeline was rewritten without its portable deployment cache; every package runs `windeployqt` afresh, is assembled in `<output>.staging` and replaces the output only when all steps passed. `dev package --rebuild-portable` is gone. Build trees are reconfigured when their recorded CMake arguments change.
- Development: manual debugging output goes to `.dev\debug`. `tools/check-layout.ps1` (run by `agent-check` and CI) rejects top-level entries missing from the repository table in `docs/workflow/overview.md`, junctions or symbolic links in the checkout, and absolute paths of the checkout or user profile; `check-docs` rejects source line numbers in docs.
- Development: branches are `dev` (default, beta releases) and `master` (stable releases); both change only through pull requests. `dev.bat check` and `dev.bat ci` run the CI gate locally, `.githooks/pre-push` runs `dev check` and refuses pushes to `master`/`dev`. GitHub CI (sccache compiler cache carried as one actions/cache archive, lld linker and no debug info through the new `SPANTUI_LINKER` and `SPANTUI_DEBUG_INFO`) is the required check on pull requests and runs again after merges into `dev`; a tree that already passed, such as a `dev` → `master` merge, is not built again, and a documentation-only pull request gets only the static checks. The tooling finds `ld.lld` in `SPANTUI_LINKER_DIR`, on `PATH` or in the default LLVM install. Test executables skip Qt's configure-time QML import scan, which took most of a reconfigure. `check-layout` also requires a UTF-8 BOM on PowerShell scripts with non-ASCII text.
- Development: the `--test-paths` option, the `SPANTUI_TEST_PATHS` CMake option and the `dev-test` data subfolder are gone; isolate runs with `--data-dir`. `--isolated-workspace` and the screenshot options no longer add a subfolder to the data root; the visual harness and `--resource-report` stay Debug-only.

## [0.1.0]

- First public release: workspace with projects and file tree, read-only code and Markdown viewer, Git status, history and diffs, ConPTY terminals with a bundled ConPTY, SSH remote hosts, themes and the standalone updater.
